# OldySend

OldySend is a fork of [LocalSend](https://github.com/localsend/localsend) for **every Android version from 1.0 (API 1) to 16**.
It speaks LocalSend protocol v2.2, so it exchanges files and messages with the official LocalSend apps on Android, iOS, Windows, macOS and Linux.

The original Flutter app needs Android 7+, so OldySend is a separate native Java app (no AndroidX, no libraries) in this folder.
The rest of the repository is upstream LocalSend and is left untouched.

## Interface styles

Settings → General → Interface style. "Automatic" picks the style of the running Android version.

| Style | Default on | Built from |
|---|---|---|
| Classic | Android 1.0–2.3 | Android 2.3.7 framework artwork (title bar, TabWidget, `btn_default`, `popup_*` dialogs, icon menu on the Menu key), Droid Sans |
| Holo | Android 3.0–4.4 | Android 4.4.4 framework artwork (action bar, stacked tabs, ON/OFF switch, Holo dialogs), Roboto |
| Material Design | Android 5–11 | Material Design 2014 spec: Toolbar, fixed tabs, raised/flat buttons, Material color palette |
| Material You | Android 12+ | Material 3 spec: top app bar, navigation bar, segmented buttons, tonal color schemes (generated with Material Color Utilities), dynamic color on Android 12+ |

Every style works on every Android version. Light/dark/system theme and an OLED mode are available; Material styles also offer a color choice.

The launcher icon follows the style (one `activity-alias` per style; `values*/launcher.xml` enables the automatic one per
Android version, `ui/Launcher.java` switches when the app goes to the background). Material You uses an adaptive icon with a
monochrome layer on Android 8+/13+. It can be turned off in the settings; some launchers drop the home screen shortcut when
the icon changes.

## Features

Everything the LocalSend mobile app does: multicast + HTTP-scan discovery, favorites, manual sending (IP / hashtag),
files, folders, media, text, installed apps (APK) and clipboard, single/multiple recipients, share via link (download page),
receive via link (upload page), PIN, quick save (all / favorites), receive options (destination, rename, gallery),
history, checksums, network interface filter, custom port and multicast group, "Share" intent,
QR codes for the share/receive links and the device verification page (the same 16-icon fingerprint as LocalSend,
`assets/verify_icons.txt` generated by `tools/gen_verify_icons.py`).

A device seen at several addresses (PCs announce from every network adapter) keeps all of them; sending tries each address
twice before failing.

Extras: keep running in the background, a built-in file/folder browser for Android versions without the Storage Access Framework,
a debug log, **Aramaic** (Syriac script, with a bundled Noto Sans Syriac font for older Android) and the joke languages
**LOLCAT** and **Cute Engwish** next to all LocalSend translations. `tools/i18n_tool.py` reports and fills missing keys.

## Encryption on old Android

LocalSend's HTTPS uses TLS 1.2 with AES-GCM and mutual certificates. Android supports those cipher suites from 5.0, so:

- **Android 5.0+**: HTTPS exactly like LocalSend (self-signed RSA-2048 certificate, fingerprint = SHA-256 of the certificate).
- **Android 1.0–4.4**: plain HTTP. These devices receive from everyone; to send *to* a device, turn off "Encryption" in that device's LocalSend settings.

## Building

Requirements: JDK 17+ and the Android SDK (platform 36, build-tools 36).

```
cd oldysend
./gradlew assembleRelease     # app/build/outputs/apk/release/app-release.apk
./gradlew lintDebug           # fails on any API newer than Android 1.0 used without a version check
```

CI: `.github/workflows/oldysend.yml` builds, lints and uploads APKs; pushing a tag `oldysend-vX.Y.Z` creates a GitHub release.
Locally the release is signed with `signing/oldysend.jks` (CN=disgusty) described by `signing/keystore.properties`
(both git-ignored; keep a backup — updates must be signed with the same key). In CI add the secrets `OLDYSEND_KEYSTORE_BASE64`, `OLDYSEND_KEYSTORE_PASSWORD`, `OLDYSEND_KEY_ALIAS`, `OLDYSEND_KEY_PASSWORD`
(otherwise the APK is signed with the debug key). APKs are v1 (JAR) signed with SHA-1, which Android 1.x requires.

Tools in `tools/`: `gen_icons.py` (Material icon paths), `gen_palettes.py` (Material 1/3 palettes), `gen_launcher.py` (launcher icon),
`shots.py` (screenshots of all styles on an emulator), `proto_test.py` / `fake_receiver.py` (protocol tests against a running app).

## Compatibility rules for contributors

- Never read `Build.VERSION.SDK_INT` (missing before API 4): use `Sdk.INT` / `Sdk.atLeast()`.
- Put newer APIs into small `@TargetApi` helper classes and call them behind `Sdk.atLeast()`.
- Java library level of Android 1.0 is Java 5: no `String.isEmpty`, `Arrays.copyOf`, `StandardCharsets`, `Objects`, `java.util.function`.
- Unqualified `drawable/` holds the mdpi artwork, because Android 1.0–1.5 ignore density qualifiers.
